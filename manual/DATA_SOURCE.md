# Where the data comes from

Back to the [README](../README.md) · [Manual](README.md)

| App | Source | Notes |
|---|---|---|
| Bionic | API of Bionic's local server at `http://127.0.0.1:1234` (or 1235) + its server logs in `%USERPROFILE%\.lmstudio\apps\bionic\server-logs` | Bionic's local server must be running (Local Server screen). Every app using it is recorded. Bionic doesn't report GPU offload — the app's own GPU / VRAM tiles measure that split from the `llama-server` process through the OS's per-process GPU counters instead. |
| Ollama | API at `http://127.0.0.1:11434` | Request stats only for apps that go through the AI_SCOPE relay — see [Configuring Ollama](CONFIGURING_OLLAMA.md). Requests are saved to `~/.ai_scope/ollama-requests.jsonl`. |
| ComfyUI | API at `http://127.0.0.1:8188` (or 8000) | Runs are saved to `~/.ai_scope/comfy-runs.jsonl`. |
| Strata | Either face of Strata: the **desktop app** at `http://127.0.0.1:47831` (its own monitor data), or the engine of a **headless `strata launch`** at its own port (`/health`, `/metrics`, `/v1/status`) | Both are read-only. By default AI_SCOPE asks the desktop app first and falls back to the CLI; the scope's **Strata source** setting pins one of them, and **Strata CLI URL** names the CLI address (empty = the port from Strata's own launch profile and runtime files, else `http://127.0.0.1:8080`). A launch started with a key needs the scope's **Strata API key** (a read-only telemetry key answers less: the page then says which faces are n/a). Installed models and Strata's fit verdicts exist only in the desktop app. Requests from both faces are saved to `~/.ai_scope/strata-requests.jsonl`, each row marked with the face it came from. |
| llama.cpp | The server's `/props`, `/models`, `/slots` and (with `--metrics`) `/metrics` at `http://127.0.0.1:9931` (`llama serve`) or `:8080` (`llama-server`); with the scope's Models folder set, the GGUF headers of that folder's files for models the router has not loaded | Request history is estimated from the slots (llama.cpp keeps no per-request timings); exact for requests that ran alone when the server has `--metrics`. Requests are saved to `~/.ai_scope/llamacpp-requests.jsonl`. |
| Processes / app Hardware tiles | Windows: its process list (`NtQuerySystemInformation`, the same as Task Manager) for CPU, RAM and I/O + its GPU performance counters for VRAM and GPU % per process. Linux: `/proc` + `nvidia-smi --query-compute-apps` / `pmon` (NVIDIA). macOS: `ps` (CPU and RAM only). An app's own process: the one listening on its port (`netstat` / `/proc/net/tcp` / `lsof`) and its children, or by name when it belongs to another user; while a model load is in progress the app's process tree is watched by name, so the loading processes are caught before the app's API reports a loaded model | One all-process sampler feeds everything: every 5 s while a Processes lens is on screen, every 30 s otherwise (changeable under **Settings → Engine → Process Refresh Rate**), and every 2 s automatically while an installed app is up and has numbers to show — the Processes lenses ride that faster pace. The last 5 minutes are kept in memory for the lenses' lines. The same numbers feed every app scope's *process* row and its Hardware Mirror Lenses. |
| Hardware | Node `os` + `nvidia-smi` (comes with the NVIDIA driver); Windows GPU counters for AMD/Intel cards on Windows; amdgpu sysfs (`/sys/class/drm/cardN/device`) for AMD cards on Linux | GPU temperature and power cover NVIDIA cards everywhere plus AMD cards on Linux (junction temp, board power and its cap from amdgpu sysfs); PCIe traffic / link is NVIDIA only (the PCIe line comes from a long-running `nvidia-smi dmon -s t` stream, the link from `--query-gpu` `pcie.link.*` fields). Disks: Windows' `PhysicalDisk` counters, Linux `/proc/diskstats`. The RAM lens's **Committed** view compares committed bytes against the PC's **commit ceiling** — on Windows from `GetPerformanceInfo` in a long-running helper, sampled every 2 s (the same value as the `\Memory\Commit Limit` counter; RAM plus pagefile), on Linux `/proc/meminfo`; the same ceiling behind an app RAM tile's Committed view. macOS: CPU and RAM only for now (no GPU or Disk tiles). |
| Settings | JSON files in the data folder: `settings-general.json`, `settings-appearance.json`, `settings-engine.json`, `settings-server.json` | Default Page, theme, Process Refresh Rate, Network Access, Start at login and Allowed host names, plus the Stop / Restart of AI_SCOPE. Saved settings win over the launch flags; Network Access and Start at login are changed by a start flag only until set in the dialog. |
